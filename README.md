# slave_upgrade —— 专网模块 Slave 固件串口升级工具（Linux CLI）

面向机载任务板（Ubuntu 20.04/22.04，aarch64）的命令行固件升级工具。
通过任务板与 Slave 模块之间的 USB 串口链路，对 Slave 进行**免断电远程固件升级**。

分块传输协议与 Windows 图形工具 **FileDownload V1.08/20260528** 完全兼容
（同步字 `A1A2A3A4` + 偏移 + 长度 + 数据 + XOR 校验的分块传输，末尾 MD5 整体校验）。
复位指令采用实机验证的序列：先发 `+++\r\n` 切回命令模式，再发 `AT+S402=1\r\n` 复位进 bootloader。

## 一、功能

| 模式 | 命令 | 说明 |
|------|------|------|
| 固件升级（默认） | `slave_upgrade firmware.bin` | 分块传输 + MD5 校验 + 写 Flash，收到 `Download OK` 即成功 |
| 版本查询 | `slave_upgrade -V` | 发送 `AT+V?` 查询固件版本；无应答时先 `+++` 切换命令模式后重试，仍无应答才回退为复位并读取启动信息 |
| 仅复位 | `slave_upgrade -r` | 发送 `+++` 切换命令模式后发 `AT+S402=1` 复位，回显启动信息（含固件版本） |
| 串口列表 | `slave_upgrade -l` | 列出 `/dev/ttyUSB*`、`/dev/ttyACM*` 设备 |
| 文件校验 | `slave_upgrade --check firmware.bin` | 仅校验文件（大小/MD5/分块数），不连接串口 |

相对 Windows 工具的增强（不改变线上协议）：

- 打开串口后**预监听 2 秒**：下位机已停留在 bootloader（如上次升级被中断）时直接续接，无需复位；
- 块应答超时（默认 **120 秒**，覆盖 SBL 擦写 Flash 的静默期）主动重发 + 连续重传上限（默认 20 次），失败即退出并报告原因；
- **复位/下载双波特率**：复位指令（`+++`/`AT+S402=1`）用 `-B` 波特率（默认 115200，模块 AT 固件当前波特率），下载固定 921600（SBL 复位后为固定速率，不可配置），全程不发 `AT+S102`、不改模块波特率配置；
- 升级总超时看门狗（默认 1800 秒，`--timeout 0` 关闭）；
- Ctrl+C 随时可中断，退出码明确，便于脚本化集成；
- 输出重定向时进度按 10% 里程碑整行打印，日志不被 `\r` 污染；
- legacy MD5 兼容模式**默认启用**（与 Windows 工具在 64 字节整数倍文件上的 MD5 行为一致）。

## 二、编译

源码无第三方依赖，仅需 gcc。

```bash
# 方式 1：在任务板上直接编译（推荐）
make

# 方式 2：静态链接（单个二进制，Ubuntu 20.04/22.04 通用，便于 scp 分发）
make static

# 方式 3：x86 主机交叉编译 aarch64 目标
make CROSS=aarch64-linux-gnu- static

# 清理
make clean
```

## 三、部署

```bash
# 在编译机上
scp slave_upgrade user@<任务板IP>:~/    # 或经 U 盘/网口拷贝

# 在任务板上
chmod +x slave_upgrade
./slave_upgrade -l                      # 确认串口设备已被识别
```

升级完成后建议保留工具与固件于任务板固定目录（如 `/opt/upgrade/`），供后续远程 SSH 升级复用。

## 四、使用

### 1. 常规升级（最常用）

```bash
./slave_upgrade firmware.bin                     # 自动探测串口（仅 1 台设备时）
./slave_upgrade -p /dev/ttyUSB0 firmware.bin     # 显式指定串口
./slave_upgrade -B 115200 firmware.bin           # 模块固件在 115200：115200 复位 + 921600 下载
```

正常输出示例（以 2782464 字节固件为例）：

```
slave_upgrade v1.0.0 开始升级（协议兼容 Windows 工具 V1.08）
读取固件文件: firmware.bin
文件大小: 2782464 字节，分 341 块（每块最大 8176 字节）
文件 MD5: 8fc415a9d5c7527b73c708d335a37af7（legacy 兼容模式）
[信息] 自动选择串口设备: /dev/ttyUSB0
串口已打开: /dev/ttyUSB0（921600 波特率, 8N1, 无流控）
等待下位机 bootloader 就绪请求（'#'）...
发送 +++ 切换到命令模式...
[RX] +++
[RX] OK
[RX] OAK-128>
发送复位指令 AT+S402=1（第 1/3 次），等待下位机进入 bootloader...
已收到下位机就绪请求（'#'），开始传输固件。
[进度] 100.0%  块 341/341  偏移 0x002A7500  平均 75.3 KB/s
下位机已确认写入完成（Download OK），耗时 45.8 秒。
升级成功: firmware.bin（2782464 字节, MD5 8fc415a9d5c7527b73c708d335a37af7）
```

说明：

- `+++` 之后模块可能回显 `OK`、命令提示符（如 `OAK-128>`）或无应答，均不影响流程；
- **进度到 100% 后会有数十秒静默**：此时下位机正在擦写 Flash，完成后回复 `Download OK`，属正常现象（详见常见问题）。

### 2. 升级确认

1. **写入确认**：收到下位机 `Download OK` / `Verify QSPI flash Passed` 即代表 MD5 校验通过且已写入 Flash；
2. **版本确认**：升级成功后工具**不再自动复位**下位机；如需确认版本，单独执行 `./slave_upgrade -V` 或 `./slave_upgrade -r`（全程默认 115200 连接，可用 `-B` 调整；`--listen` 调整监听时长，默认 8 秒）。

### 3. 复位/下载双波特率（-B）

- `-B`：**复位波特率**——连接模块 AT 固件、发送 `+++` 与 `AT+S402=1`，默认 **115200**（即模块固件当前波特率）；
- **下载波特率固定 921600**：模块复位后 SBL 固定以 921600 通信，与 AT 固件波特率无关，不可配置。

工具全程不发 `AT+S102`，不修改模块的波特率配置。模块固件波特率不是 115200 时，用 `-B` 指定：

```bash
./slave_upgrade out0827.bin             # 默认：115200 复位 + 921600 下载
./slave_upgrade -B 460800 out0907.bin   # 固件在 460800：460800 复位 + 921600 下载
```

流程：以 921600（下载波特率）打开串口预监听 2 秒（模块可能已停留在 SBL）→ 未就绪且 `-B` 不是 921600 时，**在同一串口上**切换到 `-B` 波特率，发 `+++`、`AT+S402=1` 复位 → 收到复位回显后立即切回 921600 等待 SBL 的 `#` → 传输；仍未就绪则重复复位（默认 3 次）。**全程不重开串口**（重开会清空缓冲，可能丢失 SBL 复位后立即发出的就绪帧）。`-V`/`-r` 全程使用 `-B` 波特率。

### 4. 脚本化集成

```bash
if ./slave_upgrade -q firmware.bin; then
    echo "upgrade OK"
else
    rc=$?
    echo "upgrade FAILED, exit=$rc" >&2
fi
```

`-q` 静默模式仅输出最终结果；退出码见下表。

## 五、命令行参数

```
用法:
  slave_upgrade [选项] <固件文件.bin>   升级固件（默认模式）
  slave_upgrade -V [选项]               查询下位机固件版本
  slave_upgrade -r [选项]               仅复位下位机并回显启动信息
  slave_upgrade -l                      列出可用串口设备
  slave_upgrade --check <固件文件.bin>  仅校验文件（大小/MD5/分块数，不连接串口）

选项:
  -p, --port <设备>        串口设备（如 /dev/ttyUSB0）；缺省时自动探测
  -B, --init-baud <波特率> 复位波特率（模块当前波特率），默认 115200；-V/-r 全程使用该波特率
                           可选: 9600/19200/38400/115200/230400/460800/921600/1000000/2000000
                           下载波特率固定 921600（SBL 复位后固定速率，不可配置）
      --boot-timeout <秒>  每次复位后等待就绪('#')的时长，默认 15
      --block-timeout <秒> 发送数据块后等待应答的时长（含 SBL 擦写 Flash 的静默期），默认 120
      --reset-tries <次>   复位指令重试次数，默认 3
      --retry-max <次>     连续无进展重传上限，默认 20
      --timeout <秒>       升级总超时，默认 1800，0 表示不限制
      --listen <秒>        -V/-r 复位后监听启动信息的秒数，默认 8，0 表示关闭
      --legacy-md5         兼容 Windows 工具在 64 字节整数倍文件上的 MD5 行为（当前默认已启用）
  -v, --verbose            输出详细日志（含每块收发）
  -q, --quiet              静默模式（仅输出最终结果，适合脚本调用）
  -h, --help               显示帮助
      --version            显示工具版本
```

## 六、退出码

| 退出码 | 含义 | 常见原因 |
|--------|------|----------|
| 0 | 成功 | — |
| 1 | 参数错误 | 选项值非法、缺少固件文件 |
| 2 | 串口错误 | 设备不存在、无权限、传输中 USB 断开 |
| 3 | 文件错误 | 文件不存在 / 为空 / 超过 8MB 上限 / 读取失败 |
| 4 | 超时 | 链路中断、波特率不匹配、下位机未就绪、总超时 |
| 5 | 重传超限 | 链路质量差、MD5 校验不匹配、下位机异常 |
| 6 | 用户中断 | Ctrl+C |

## 七、常见问题

**Q: 提示"未发现串口设备"？**
确认任务板上 `ls /dev/ttyUSB*` 存在；不存在时执行 `dmesg | tail` 检查 USB 枚举（常见为 ch341/cp210x/ftdi，Ubuntu 20.04+ 内核自带驱动）。

**Q: 打开串口报 Permission denied？**
将当前用户加入 dialout 组后重新登录：`sudo usermod -aG dialout $USER`。

**Q: 进度 100% 后长时间没有输出？**
正常现象：数据块与 MD5 块发完后，下位机 SBL 开始擦除并烧写 Flash（2.7MB 约需数十秒甚至更久），期间完全静默，完成后回复 `Download OK`。块应答超时默认 120 秒，超时才会重发 MD5 块；若下位机烧写耗时超过 120 秒，用 `--block-timeout 300` 加大后重跑。
注意：即使工具中途超时退出，下位机可能仍在继续烧写并最终成功——建议先断电重启模块、用 `-V` 确认固件版本后再决定是否重刷。

**Q: 等待就绪（'#'）超时？**
1. 观察复位后有无 `[RX]` 输出：完全无输出多为链路/供电问题；有乱码多为波特率不匹配；
2. 波特率不匹配时用 `-B` 指定模块当前波特率（复位阶段；下载固定 921600，无需也无法调整）；
3. 检查任务板与 Slave 之间的 USB 串口线序；
4. 先用 Windows 工具在同一链路上验证硬件连通性。

**Q: 传输中频繁"下位机请求重发"？**
多为链路干扰（串口线质量、USB 供电、接地），可换线或换 USB 口重试；下载波特率固定 921600，无法降低。若始终在 MD5 阶段失败，用 `test_md5 <固件文件>` 对比 std/legacy 两种摘要，排查 MD5 兼容问题（legacy 模式当前默认启用）。

**Q: 升级中断电/中断了怎么办？**
下位机 bootloader 未收到完整固件前不会写 Flash，原固件不受影响；重新执行升级即可。若上次中断后下位机已停留在 bootloader，本工具打开串口后预监听 2 秒直接续接，无需额外操作。

## 八、源码结构与协议说明

```
slave_upgrade/
├── main.c        CLI 入口：参数解析、模式分派、信号处理
├── protocol.c/h  升级协议状态机（预监听 → +++/复位 → '#' 握手 → 分块传输 → MD5 → Download OK）
├── serial.c/h    Linux termios 串口封装（8N1、poll 超时、设备枚举）
├── md5.c/h       MD5 实现（含 legacy 64 字节对齐兼容模式）
├── test_md5.c    MD5 自测程序（开发用）：test_md5 <文件> 输出 std/legacy 两种摘要
└── Makefile      构建（本机 / 静态 / aarch64 交叉）
```

协议细节（传输部分与 FileDownload V1.08 的 `handle_loop_data()` 状态机逐字节对齐）：

- 同步字 `0xA4A3A2A1`（线上字节序 `A1 A2 A3 A4`）；XOR 校验初值取同步字，覆盖 偏移 + 长度 + 数据（不足 4 字节按 0 补齐）；
- 单块数据上限 **8176 字节**（8KB-16；Windows 工具为 163824，线上格式一致，下位机按长度字段自适应）；
- MD5 块：偏移 `0xFFFFFFFE`，长度 16，数据为固件 MD5 摘要；
- 应答判序：`*` 确认（发下一块）/ `^`、`#` 重发当前块 / `Download OK`、`Verify QSPI flash Passed` 升级成功；
- 复位序列（实机验证）：`+++\r\n`（切回命令模式，等待并回显应答）→ `AT+S402=1\r\n`（复位）→ 等待 bootloader 发出 `#`。
